# OpenShell issues: 15 приоритетов для Cauteum Docker/Podman

Срез: 2026-10-09. Источник — открытые issues [NVIDIA/OpenShell](https://github.com/NVIDIA/OpenShell/issues), просмотренные по числу комментариев, недавним обновлениям и темам Docker, Podman, gateway, supervisor, policy, proxy и CLI. Приоритет ниже — **наш**: тяжесть для безопасности и сохранности данных, частота обычного сценария, ширина затронутых клиентов и возможность исправить в текущей архитектуре. Число комментариев и upstream labels служат дополнительным сигналом. В список не входят Kubernetes и VM. Открытый upstream issue означает проблему в OpenShell, а не доказанный дефект Cauteum; где нет собственного воспроизведения, первым шагом указан точный probe.

Наш закреплённый OpenShell commit `a0814443f19c07102b19ff09d6ead3d3ba59f9c5` старше части этих issues. Переносить новое поведение в совместимый wire protocol следует только после сверки с закреплённой схемой и плана версии/миграции. Текущий код и исторические отметки о проходивших проверках не заменяют нового Docker/Podman результата.

Конкурентный fixture ещё не запускался.

## План исполнения

### Волна A — границы безопасности и запись состояния (1–5)

#2336: есть только смежная opt-in mitigation для named volume /cauteum/data. Она не закрывает исходный сценарий ownership drift на bind-mounted state/workspace. Следующий шаг — определить cauteum-owned persistent bind paths и применить только к ним стабильный mapping или opt-in reconcile; произвольный workspace не менять.
1. **#3911:** запустить одинаковый сценарий `hard_requirement` на Docker, rootful Podman и rootless Podman с доступным Landlock и с ABI 0/отключённой поддержкой. Проследить policy YAML → driver spec → `harden.Apply` → запуск workload; закрыть любой путь, где workload стартует после отказа обязательной изоляции. Готово, когда недоступный Landlock даёт отказ до запуска и диагностическое событие, а `best_effort` явно сообщает о снижении защиты.
2. **#4253:** протащить фактическую схему `http`/`https` и `ws`/`wss` через proxy request model до `HttpRequestTarget`; исключить вывод схемы из номера порта или hardcoded значения. Готово, когда middleware fixture получает точную схему для plaintext HTTP, TLS MITM и WebSocket; решение deny/allow использует именно переданное значение.
3. **#3308:** воспроизвести разрыв SSH/relay при живом supervisor и падение supervisor при сохранном backend отдельно. Задать допустимые переходы `Ready/Error/Stopped`, сравнить живую runtime instance с durable record и добавить восстановление без удаления workspace; устаревшее событие не должно сбивать новый запуск. Готово, когда stop/start или автоматическое восстановление выводит sandbox из Error после обоих сценариев, а workspace сохраняется.
4. **#2336:** текущий opt-in reconcile исправляет только named volume /cauteum/data и не считается закрытием issue. Для реального bind-mounted state определить ownership и границы выделенного Cauteum каталога, затем сверять mapping и применять pinning либо opt-in reconcile только в этой границе. Готово, когда смена subuid после reboot восстанавливает доступ к данным и не меняет файлы за пределами выделенного каталога.
5. **#4062:** перечислить все sandbox/global policy write пути: Control, OpenShell UpdateConfig/merge, proposals, provider refresh и recovery. Каждая успешная ревизия должна атомарно увеличивать sandbox resource version, а устаревший `expected_resource_version` отклоняться. Готово, когда две независимые записи с одной исходной версией не могут обе пройти, включая глобальное обновление и повторный запрос.

### Волна B — сеть, доверие и входные точки (6–9)

6. **#4278:** проверить HTTP/80 и HTTPS/443 через локальный CONNECT-only upstream. CONNECT establishment уже bounded и context-aware. Если proxy запрещает CONNECT к port 80, сохранить быстрый явный `502`/audit failure; если разрешает, подтвердить relay plaintext HTTP внутри туннеля. Готово, когда порт 80 доставляет ответ либо быстро и явно отказывает, без зависшего соединения и без обхода egress policy.
7. **#3781:** проверить, что `egress_ca_bundle` доступен sidecar на Docker и Podman, и подтвердить private-CA HTTPS, публичные сертификаты, неверный CA и rotation через recreate. Сейчас bundle добавляет trust roots только в sidecar upstream TLS client; workload image и gateway auth trust не меняются.
8. **#3674:** проверка кода не выявила подмены внутреннего адреса на внешний authority: используемый CLI/SDK gateway URL уже содержит внешнюю схему, а relay transport следует https. Остался live probe через TLS termination: SSH connect, exec и port forwarding должны проходить без plaintext на внешнем listener; проверить TLS SAN и HTTP Upgrade.
9. **#3880:** loopback endpoint уже преобразуется в host.docker.internal; gateway теперь объясняет grpc_endpoint и guest TLS при relay timeout. Осталось проверить WSL2 Docker Desktop и Linux Docker: маршрут, TLS SAN и host-gateway isolation. Не ослаблять изоляцию workload ради маршрута.

### Волна C — создание, потоки и матрица драйверов (10–13)

10. **#2675:** инъецировать ошибку pull/create/start/supervisor bootstrap и фиксировать durable registry, containers, volumes, tokens и повторное create с тем же именем. Выбрать единый контракт: автоматический rollback до подтверждения create, затем явный recover/delete для уже созданного ресурса. Готово, когда пользователь может безопасно повторить запрос с тем же request ID и не получает скрытых ресурсов или потери workspace.
11. **#2676:** проверить private registry pull через Docker credential helper и Podman authfile на реальных daemon; проверить отказ без credentials и отсутствие секретов в логах/metadata. Driver-level resolver уже передаёт auth только в Engine pull API. Готово, когда оба положительных сценария проходят, отрицательный сценарий понятен и credentials не раскрываются.
12. **#3056:** ForwardTcp и RelayStream теперь ждут EOF обоих направлений; ConnectSupervisor RelayClose aborts active channel, а потеря control-сессии закрывает её каналы. Остаётся согласовать и документировать lifecycle state machine для всех четырёх RPC, capability negotiation для frame-level half-close, terminal status/timeout/retry semantics и одинаковые helper API в SDK. Добавлять wire поля только после зафиксированной схемы skew. Готово, когда integration/fault-injection подтверждают half-close, drain, cancel и timeout, а Go/Python/TypeScript/Rust клиенты ведут себя одинаково.
13. **#3712:** rootful driver CI запускает четыре Testcontainers E2E; отдельный Linux job запускает rootless service recovery и userns auto/host на disposable Podman 6.1.3. Все обязательные сценарии требуют явных PASS-маркеров; оба job и driver OS matrix прошли в GitHub Actions для draft PR #5. Осталось закрыть gateway/SSH lane и оставшиеся rootless userns modes; capability limitations отмечать отдельно от общего PASS.

### Волна D — диагностика до create (14–15)

14. **#4133:** `doctor check` должен запускать тот же Landlock/host-network/endpoint probe, от которого зависит создание Docker sandbox, и объяснять, какая предпосылка отсутствует. Готово, когда заведомо несовместимый Docker Desktop даёт failure с действием для оператора, а поддерживаемый проходит без ложного отказа.
15. **#3694:** выбирать doctor probes по реально настроенному gateway driver; для Podman проверить socket, серверную версию, rootless режим, userns/network helper и host-gateway ограничение. Готово, когда запуск без Docker на работоспособном Podman не требует Docker и печатает Podman-специфичную диагностику.

## Порядок закрытия и проверка

- Для каждого пункта сначала зафиксировать локальное воспроизведение или отметку «у нас не воспроизводится» с версией engine, ОС, режимом rootless/rootful и конфигурацией. Это не переносит автоматически upstream bug в наш backlog как подтверждённый дефект.
- После изменений проверить соответствующий сценарий на Docker и на применимых Podman lane. Для чисто CLI/RPC логики использовать оба driver fixtures. Не считать Podman 5 capability skip проверкой Podman 6 host-gateway защиты.
- В связанной записи хранить commit/PR, результат положительного и отрицательного сценария, а также изменённый публичный контракт/SDK, если он есть. Обновить `openshell_compatibility_gaps.json` и EN/RU документацию только по подтверждённому поведению.
- Зависимости: 1 и 2 до расширения политики; 3 и 5 до автоматических retry; 6 и 7 до обещания private network access; 13 нужен как release gate для всех Podman пунктов. Волны допускают параллельную работу по модулям после фиксации этих контрактов.

За пределами первой пятнадцатки остаются [#4102 GNU Make](https://github.com/NVIDIA/OpenShell/issues/4102) и [#4098 Chromium sandbox](https://github.com/NVIDIA/OpenShell/issues/4098): upstream использует иной набор seccomp/namespace ограничений, поэтому сначала нужен локальный probe.
