## Client API and Cauteum management console (2026-10-08)

Decision: use OpenShell's contract-first RPC approach for CLI, UI, and SDK clients. The pinned OpenShell gRPC contract remains authoritative for upstream runtime workflows; `cauteum.control.v1` is the narrower user-authorized Cauteum API. Connect serves browser clients and native gRPC serves native clients. Do not preserve REST `/v1` for compatibility or add new features there. Move client workflows to RPC, then remove the legacy REST client surface and OpenAPI contract; beta callers may need to update. The [UI API catalog and phase table](RPC_SDK_UI_ARCHITECTURE.md#ui-client-api-plan) define the method boundaries and migration sequence.
